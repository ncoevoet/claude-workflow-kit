# Delegation rules — rationale and incidents

> Loaded on demand — not part of the SessionStart payload. The one-line rules live in
> `context/orchestration.md`.

- **Subagents never run state-changing git** — `add`, `commit`, `push`, `stash`, `checkout`, `restore`, `reset`, `rebase`, `merge`, `cherry-pick`, `switch`, `clean` — nor write the main session's compaction checkpoint (`.claude/.compact-gate/**`). The main session owns git state and hands over a clean index. Hook-enforced (`subagent-guard.sh`) by detecting the subagent-only `agent_id` field on the hook payload — this is not prose alone, because prose alone was broken: a builder once ran a project's translation-regenerating npm script followed by a destructive git checkout, silently discarding a sibling agent's uncommitted work. A project can deny additional command patterns via `.claude/subagent-deny.txt` (one ERE per line).
- **Verifiers and judges run against a frozen build — a static build or a deployed target — never the hot-reloading dev server a builder is actively editing.** A builder's in-progress TypeScript error surfaces as an overlay that intercepts the verifier's clicks and produces a false FAIL; a passing check that was actually looking at someone else's mid-edit state is not a check.
- **Gate cadence.** Per wave: the static gates (typecheck, lint, architecture) **in parallel**, on a tree no builder is currently editing, then the commit gate's review. **Tests run in the pre-push hook, never per wave or per commit** — a suite costs minutes on every commit, and a run on a moving tree is stale the moment the next edit lands. The one exception is running the spec you are writing or fixing, to see it fail then pass. A repository with no test step in its pre-push hook runs the suite once, just before `git push`. **Commit locally after each verified wave** — this is not pushing, and does not require push approval; it turns a wave's result into a `git show` away instead of something reconstructed from transcripts if a later step goes wrong.
